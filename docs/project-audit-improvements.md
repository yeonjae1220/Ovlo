기준일: 2026-11-24 KST. 기준 커밋: `ff02a6c7d8a6a022b902868e86dd4f97e9ac1c70`.
작업 브랜치: `codex/project-audit-improvements`.

기존 점검의 18개 항목을 여섯 단계로 나누어 개선했다. 변경은 별도

## 보존한 설계 원칙

- Member, MediaFile, ChatRoom의 엔티티/ID 경계를 유지하고 도메인에 Spring/JPA 의존성을 추가하지 않았다.
- 저장소 접근은 application port를 통한다. 서비스에서 JpaRepository를 직접 주입하지 않는다.
- 반응의 조건부 DML·원자 카운트, 캘린더의 소유권·학교 배정·버전, 국제처의 동의/보존 정책, 중고거래의 버전·차단·사진 정리 규칙을 유지한다.
- 일반 미디어와 중고거래 사진은 별도 저장 모델이다. 이번 삭제 큐를 중고거래 첨부 사진 삭제로 확대하지 않는다.
- 기존 탈퇴 ID는 복구하지 않는다. 이후 가입은 새 신원으로 처리한다.

### 조회 비용과 복원

미읽음 집계는 Testcontainers PostgreSQL에서 방당 메시지 100개, 20회 측정했다.
최근 실행 p95는 1방/100건 4.25 ms, 50방/5,000건 12.78 ms, 500방/50,000건 29.25 ms다.
이는 저장소 함수 시간이며 HTTP p95·동시 사용자 수·운영 처리 용량의 측정값이 아니다.
운영에서 증가 가능한 방 목록 전체의 응답 크기 제한은 후속 검토 대상이다.

합성 DB를 `pg_dump -Fc`로 내보내고 별도 DB에 복원했다. 193,956바이트 덤프,
1,654 ms의 로컬 실행에서 탈퇴 익명화와 미디어 삭제 대기 작업 보존을 확인했다.
실제 파일 삭제 실패 후 큐/파일을 보존하고 재시도 성공 시 둘을 정리하는 테스트도 통과했다.
이 숫자는 운영 백업의 RTO/RPO나 NAS 복구 성능을 뜻하지 않는다.

- `build/reports/audit/chat-unread.csv`, `build/reports/audit/synthetic-restore.txt`
- 이번 브라우저 캡처: `/tmp/ovlo-project-audit-browser/`, `/tmp/ovlo-auth-race-browser/`

집중 실행은 Gradle 테스트 보고서를 덮어쓰므로 전체 실행 결과와 혼동하지 않는다.

## 운영 반영 절차

### 반영 전

1. 현재 배포 커밋과 마이그레이션 최댓값을 확인한다. V54·V55를 추가하며 기존 V41~V53를 수정하지 않는다. 다른 변경이 병합되었다면 번호 충돌을 먼저 해결한다.
2. NAS의 실제 DB/미디어 백업에 대해 최신 도착 시각·크기·압축 무결성·복원 가능성을 확인한다. 로그의 성공 문자열만으로 판단하지 않는다.
3. 운영 백업을 접근 제한된 별도 환경에 복원하고 최신 Flyway를 적용한다. 파일 참조·권한·탈퇴 조회 차단·삭제 큐를 검증한다.
4. 아래 읽기 전용 쿼리로 변경 후보를 확인한다. 과거 탈퇴 계정 익명화 플래그는 검증이 끝날 때까지 활성화하지 않는다.

```sql
-- V54 적용 후: 개인정보 본문을 출력하지 않는 수량 확인
SELECT count(*) AS pending_legacy_erasure
FROM member WHERE status='WITHDRAWN' AND personal_data_erased_at IS NULL;

SELECT id, name_en, country, country_code
FROM global_universities WHERE id=5056;

SELECT count(*) AS jobs, max(attempts) AS max_attempts,
       min(next_attempt_at) AS earliest_attempt
FROM media_deletion_job;
```

### 배포·과거 계정 정리

일반 파일 삭제 작업은 기본 활성화된다
(`ovlo.media.cleanup-enabled=true`, 60초 간격, 50건, 실패 시 5분 뒤 재시도).
파일 저장소를 실제로 읽고 삭제할 수 있는지 별도 환경에서 확인한다.

과거 탈퇴 계정 일괄 익명화는 `ovlo.privacy.legacy-erasure-enabled=true`를 명시했을 때만 실행한다.
기본값은 비활성이다. 한 번에 50명씩 현재 WITHDRAWN 상태를 잠그고 처리하며
진행 로그에는 처리 건수와 남은 건수만 남긴다. 운영에서 아직 실행하지 않았다.
검증된 백업·복원·대상 수량 확보 이후에만 활성화하고 잔여 수가 0이 되면 다시 비활성화한다.

배포 후 로그인/재발급, 학교 담당자·국제처 권한, 프로필 사진, 게시판/댓글,
채팅 단절 복구, 서비스 워커 업데이트, 파일 정리 지연과 실패율을 확인한다.
실제 삭제 큐가 줄고 저장소 파일이 제거되는지도 함께 확인한다.
운영 알림 임계치와 수신 경로는 트래픽/보존 정책에 맞춰 확정해야 한다.

### 복원·롤백

V54 이전 백업에는 익명화 전 개인정보가 있을 수 있다. 복원 환경을 먼저 외부와 격리하고
현재 탈퇴/삭제 기록과 대조해 정리한 뒤 노출한다. 이전 앱 이미지로 되돌리면 옛 접근 정책이
재등장할 수 있으므로 권한·탈퇴 회귀 검사 없이 롤백하지 않는다.
삭제한 파일은 자동으로 복원하지 않으며 백업 보존 기간/삭제 전파는 운영 정책에 포함한다.

## 남아 있는 확인과 제한

- **사용자 요청으로 보류:** 공개 운영 문의 이메일, 외부 AI 처리 주체·전송 내용·보관/삭제 조건. 확정한 뒤 개인정보 문서의 기능 상태와 동의 버전을 함께 검토한다.
- **운영 접근 제한:** 이번 NAS SSH는 `Permission denied (publickey,password)`로 실패했다. 최신 백업 도착·미디어/Redis 복원·알림 수신·노드 장애 전환을 검증했다고 주장하지 않는다.
- **외부 AI:** 실제 모델 호출 검사 26개는 opt-in 상태로 건너뛰었다. 합성 검색·인용·권한·비용 제한 검증은 실제 모델 답변 품질 평가를 대체하지 않는다.
- **제공 정보 사실성:** 724개 리포트의 학비·기숙사·비자·협정 조건을 공식 출처와 전수 대조하지 않았다. 국가/언어/기준일별 표본의 출처·확인일·금액/통화·모집 기간을 검증하고, 미확인 내용은 추정으로 채우지 않는 절차가 필요하다.
- **미디어:** HEIC/WebP 신규 업로드는 미지원이다. JPEG/PNG 원본 EXIF/색상/방향은 유지하며 개인정보 메타데이터 제거를 보장하지 않는다. MP4는 컨테이너 헤더 검사만 하며 전체 영상 디코딩/변환은 하지 않는다. 일반 업로드의 계정별 저장량 한도와 모든 미사용 파일 정리는 추가 설계 대상이다.
- **탈퇴 보존:** 일반 게시글·댓글·메시지는 기존 숨김 정책을 유지한다. 법적/운영상 보존 기간을 새로 정하지 않았다. Redis refresh는 현재 DB 상태로 사용을 차단하며 모든 임시 키를 즉시 물리 삭제하는 기능은 추가하지 않았다. 국제처의 기존 동의/감사/보존 규칙을 유지한다.

후속 운영 작업을 완료하기 전까지 위 항목을 해결된 것으로 표시하지 않는다.
