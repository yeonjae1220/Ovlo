# 중고거래 · 묶음 판매 · 무료 나눔

## 사용자 흐름

`/marketplace`에서 로그인 회원이 상품을 검색한다. 국가·도시·학교·카테고리·요청 통화·상황 태그로
필터링하며, 무료 나눔·묶음·거래 가능 여부를 추가 선택한다. 최신순 20건 페이지이며 도시명은
대소문자를 구분하지 않는 일치 검색이다. 학교는 거래 위치이고 해당 학교의 인증을 의미하지 않는다.

`/marketplace/new`에서 사진 1~8장을 올리고 순서를 조정한다. 첫 장이 대표 사진이다.
단품/묶음과 판매/무료 나눔을 독립적으로 선택한다. 제목과 구성 설명은 필수다.
사진에 보이지만 제외되는 물건·하자·남은 물건을 설명에 적도록 안내한다.
부분 수령은 묶음에만 허용하며, 품목별 재고·예약 기능은 없다. 판매자가 설명과 사진을 수정한다.

- 상황 태그: `RETURN_HOME`(귀국 정리), `MOVING_OUT`(이사 정리), `ARRIVAL_ESSENTIALS`(입국 생활용품).
- 카테고리: 생활용품, 가구, 전자기기, 교재·책, 의류, 여러 종류, 기타.
- 가격은 묶음 전체 금액이다. 무료 나눔은 0, 판매는 양수다.
- 수령 가능 시작일·마감일은 선택 사항이며 거래 장소의 현지 날짜, 양끝 포함이다.
- 사용자 화면 문구는 한국어/영어이며, 다른 화면 언어에는 영어를 표시한다. 아래의 게시글 번역은 9개 언어를 지원한다.

## 통화와 번역

`AskingPrice`는 `BigDecimal` 금액과 ISO 통화 코드로 구성된다. 거래 국가와 독립적이므로
프랑스에서 거래하면서 KRW를 요청할 수 있다. 서버에서 통화별 소수 자릿수를 검사한다.
금액은 DB `NUMERIC(20,8)`로 저장해 소수 4자리 통화도 보존한다. 자동 환전·환율·결제는 제공하지 않는다.

원문 언어는 작성자가 선택한다. 상세 화면에서 ko/en/ja/zh/es/fr/de/pt/ru로 제목·설명을 번역하고
원문으로 전환할 수 있다. 구조화된 가격·통화·날짜·사진은 번역으로 덮어쓰지 않는다.
번역은 `(listing_id, version, language)`별로 캐시하며 글 수정·상태 변경·숨김으로 버전이 바뀌면 무효화한다.
LLM 호출 중 DB 트랜잭션을 유지하지 않는다. 호출 후 글 잠금과 버전·공개 여부를 재검사한다.

기존 `ovlo.llm.provider=anthropic` 설정과 API 자격증명을 재사용한다. `fake` 또는 미설정 환경은
가짜 번역을 보여주지 않고 503을 반환한다. 실패 시 화면은 원문과 재시도 가능한 오류를 표시한다.
실제 외부 모델의 번역 품질은 자동 테스트 범위 밖이며, 테스트는 번역 포트를 대역으로 검증한다.

## 도메인·권한·동시성

`marketplace`는 별도 Bounded Context다. `Listing`은 엔티티,
`ListingDetails`, `AskingPrice`, `PickupLocation`은 순수 Java 불변 값 객체다.
일반 `Post` 테이블에 상품 데이터를 중복 저장하지 않는다. 기존 `TRADE` 게시판 상세에는 새 중고거래 링크를
제공하며 기존 게시글을 자동 변환하거나 삭제하지 않는다.

- 현재 DB 회원 상태가 `ACTIVE`여야 한다. 등록·사진 업로드는 기존 `STUDENT` 이상 신뢰 등급을 요구한다.
- 작성자만 내용·상태 변경·삭제 가능하다. 오래된 `version`의 쓰기는 409다.
- `AVAILABLE`, `RESERVED`, `PARTIALLY_TAKEN`, `COMPLETED` 상태. 부분 완료는 부분 수령을 허용한 묶음만 가능하다.
- 완료는 종결 상태다. 완료 후 내용 수정·판매 재개는 막고 삭제는 가능하다. 결제 확인을 뜻하지 않는다.
- 사진은 JPEG/PNG, 장당 8MB·4천만 화소 상한이며 긴 변을 최대 1600px로 줄여 JPEG로 재인코딩한다.
  원본 EXIF 등의 메타데이터는 저장하지 않는다. HEIC/WebP는 이번 업로드 경로에서 지원하지 않는다.
- 파일은 기존 `StoragePort`로 저장하지만 일반 `media` 테이블에 넣지 않는다. 전용 사진 API에서 로그인·차단·
  숨김·삭제 상태를 검사한다. 미첨부 사진은 업로더만 조회한다. 응답은 `no-store`이고 브라우저는 인증된 blob을 표시한다.
- 업로드 실패 시 트랜잭션 롤백으로 생성 파일을 정리한다. 등록을 포기한 미첨부 사진의 주기적 보관기간 정리는 후속 운영 작업이다.
- 상품+구매자별 대화방은 두 명으로 구성된 전용 `GROUP`이다. 일반 회원쌍 DM 재사용과 분리된다.
  상품 행 잠금과 DB 유니크 제약으로 동시 문의도 방 하나를 반환한다. 기존 채팅 송수신·읽음을 재사용한다.
- 차단은 상호 상품 조회·새 문의·기존 중고거래방의 새 메시지를 막는다. 과거 대화는 보존한다.
  일반 DM의 차단 정책까지 변경하지 않는다.
- 글쓰기/문의/신고 10분 30회, 사진 시간당 80회, 번역 분당 10회·하루 100회로 회원별 제한한다.

## 운영

`/admin/marketplace`에서 최근 신고 100건을 확인하고 숨김·복구한다. 기존 관리자 세션과 CSRF 체인을 사용한다.
회원 JWT의 ADMIN 역할로 접근할 수 없다. 조치는 `marketplace_audit`에 기록한다.
일반 회원 응답은 판매자의 ID·닉네임만 포함하고 이메일·연락처 등 개인정보를 싣지 않는다.

스키마는 `V43__marketplace.sql`. 기존 스키마를 변경하지 않고 상품·사진 연결·대화 연결·신고·차단·번역 테이블을
추가한다. API를 제공하려면 마이그레이션을 먼저 적용해야 한다. 되돌릴 때 새 테이블을 삭제하지 않고 이전 앱 버전으로
복귀해 데이터를 보존한다. 새로 저장한 파일도 유지한다. 운영 배포·실제 LLM 자격증명 변경은 구현 작업에 포함하지 않았다.

## 검증

```bash
./gradlew test
./gradlew integrationTest
./gradlew integrationTest --tests '*MarketplaceIntegrationTest'
cd frontend
npx tsc --noEmit
npx eslint src/views/marketplace src/api/marketplace.ts 'src/app/(protected)/marketplace'
npm run build
# 별도 Next 서버 + Playwright 설치 경로가 필요하다. API는 테스트 fixture로 대체한다.
MARKET_URL=http://localhost:3317 PLAYWRIGHT_MODULE=/path/to/playwright node scripts/test-marketplace-browser.cjs
```

통합 테스트는 실제 PostgreSQL 16·전체 Flyway·보안 필터를 사용한다. 사진 소유권과 공개 범위,
다중 사진/무료 나눔, 통화 필터, stale version, 관리자 CSRF, 동시 문의, 차단 후 메시지,
번역 캐시와 수정 중 번역 경합을 검증한다. 브라우저 검증은 모바일 등록/필터/번역 동작 및 multipart 요청을 검증한다.
