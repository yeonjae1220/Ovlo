# ADR-0009: 공지 번역 무결성 검증과 영속 재시도

- 상태: Accepted
- 날짜: 2026-11-16

## 문제

기존 숫자 게이트는 원문 숫자의 최소 출현 횟수만 확인했다. 원래 등록비 15유로를 남긴 채 900유로를 추가하거나 연락처를 바꾼 결과가 저장될 수 있었다. 등록비 15유로와 보증금 150유로를 서로 바꾸면 숫자 집합도 같아 코드 검사만으로 발견할 수 없었다.

승인 직후 비동기 번역은 일회성이었다. 같은 담당자가 공지 두 건을 승인하면 회원 동시 호출 제한으로 두 번째 공지의 모든 언어가 실패하고 수동 재번역 전까지 복구되지 않았다.

## 결정

1. 날짜·시간뿐 아니라 숫자 값과 출현 횟수를 정확히 비교한다. URL·이메일의 추가·삭제·변경도 거절한다. 기존 소수점·천 단위·언어별 날짜 처리는 유지한다.
2. 코드 검사를 통과한 결과만 독립 Sonnet 검증에 전달한다. 원문·번역을 JSON 데이터로 분리하고 금액의 대상, 단위, 조건, 부정문, 누락·추가 사실을 대조한다. 엄격한 ALLOW/DENY 스키마를 사용하며 거부·불완전·잘못된 응답·통신 실패는 저장하지 않는다. 번역은 Opus, 검증은 답변 모델 설정의 Sonnet을 사용한다. 폴백과 SDK 자동 재시도는 끈다.
3. 공지 번역 1회는 최대 2번의 유료 호출이므로 기존 회원·학교·전역 한도에서 토큰 예산을 2배 예약한다. 일일 횟수는 번역 시도 단위이고, 토큰 예약은 실패 시에도 반환하지 않는다. 작업과 동시 호출 슬롯은 300초 동안 유지해 각각 최대 90초인 두 호출을 포괄한다.
4. V48은 `integrity_verified`와 공지·원문 버전·언어별 `notice_translation_job`을 추가한다. 기존 MACHINE 번역은 검증 전까지 stale로 취급해 학생 표시 및 챗봇 근거에서 제외한다. 이미 사람이 REVIEWED한 번역은 유지한다. 현재 승인된 공지의 누락·기계 번역은 마이그레이션에서 작업을 등록한다.
5. 승인과 작업 등록을 같은 DB 트랜잭션에서 처리한다. 커밋 후 이벤트는 즉시 처리하고, 스케줄러는 10초 간격으로 남은 작업을 회수한다. 행 소유권은 DB 시각·UUID로 검사하며 300초 후 복구할 수 있다. 오래된 소유자는 결과를 저장하거나 새 작업을 종료하지 못한다. 외부 호출 중에는 DB 트랜잭션을 유지하지 않는다.
6. 동시 호출 제한은 30초 후, 일일 한도는 다음 UTC 날짜에 재시도한다. 대기는 유료 시도를 소비하지 않는다. 외부 호출 전에 DB 시도를 증가시켜 프로세스 종료도 횟수에 포함한다. 원문 버전·언어별 최대 3회, 작업 수명은 48시간이다. 통신 오류는 300초 후 재시도하고 검증 거절은 자동으로 반복하지 않는다. 담당자는 60초 뒤 수동 재번역할 수 있지만 같은 횟수·수명 제한을 공유한다. 소진된 작업은 원문을 수정·재승인해야 새 버전으로 생성한다.
7. 보관·만료·원문 변경·학교 정지에 해당하는 대기 작업은 취소한다. 저장 직전에 현재 원문·학교 상태와 DB 및 Redis 소유권을 다시 검사한다.

## 결과와 한계

정상 공지의 번역 비용에는 언어별 Sonnet 검증 1회가 추가된다. 기존 기계 번역을 재검증하는 동안 일부 언어는 원문으로 표시되거나 챗봇 근거가 없을 수 있다. 재시도는 기존 누적 비용 한도를 공유하므로 한도가 소진되면 완료가 다음 날로 넘어갈 수 있다.

LLM 의미 검증은 확률적이며 모든 의미 오류를 증명하여 제거하지는 못한다. 코드 게이트, 독립 검증, 담당자 검토를 함께 사용한다. 중요한 공지는 담당자가 최종 번역을 검토한다. 운영 점검은 `notice_translation_job`의 PENDING/RUNNING/REJECTED/FAILED/CANCELLED 상태와 `translation-verify` 모델·토큰 메트릭을 확인한다. 원문과 학생 정보는 운영 로그에 추가하지 않는다.

운영 검증에서 제목의 구분 기호 `나`를 `B`로 옮긴 번역이 의미 검사에서 보류되는 사례를 재현했다. 문서 식별자·목차 기호는 원문 문자 그대로 보존하고, 의미 검사도 보존된 기호를 미번역 본문으로 판단하지 않도록 명시한다. 금액·조건·누락 사실 검증은 유지한다. 보류 로그에는 원문 대신 `structure`/`semantic` 단계만 기록한다.

## 검증

숫자 추가·반복, 연락처 교체, 금액 대상 바꾸기, 조건 반전, 잘못된 JSON·중복 필드·잘린 응답, 두 호출 비용 예약, 오래된 작업 소유권, 시도 소진, 기존 미검증 번역 제외를 회귀 테스트로 고정한다. PostgreSQL·Redis 통합 테스트는 같은 담당자의 동시 공지가 수동 API 호출 없이 재시도되는지 확인한다. 실제 LLM 테스트는 합성 공지만 사용하며 별도 opt-in으로 실행한다.
