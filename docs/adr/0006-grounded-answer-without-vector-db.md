# ADR-0006: 파일럿의 근거 검색은 벡터 DB 없이 PostgreSQL FTS + LLM 인용 검증으로 한다

- 상태: Proposed
- 날짜: 2026-10-30
- 결정자: Backend
- 관련 설계: [국제처 파일럿 제품 설계](../intl-office-pilot-design.md) §5.2, §8
- 관련 Pitfall: GLOBAL-PIT-064(게이트 화이트리스트 맹점), GLOBAL-PIT-108(실패를 빈 값으로 치환 금지)

## 맥락

학생 질문에 "국제처 승인 자료만 근거로" 답하려면 (1) 후보 자료를 고르고 (2) LLM이 후보 안에서만 답하게 하고 (3) 그 답이 실제로
후보를 인용했는지 확인해야 한다. 일반적인 방법은 임베딩 + 벡터 DB(pgvector 등)다.

파일럿 조건: Office 1곳, 승인 자료 수십~수백 건, 언어 7개. 운영 DB는 k3s의 PostgreSQL 16이며 확장(pgvector) 추가는 이미지 교체와
백업·복구 절차 확인이 필요하다. 임베딩 모델 선택·갱신(자료 수정 때마다 재임베딩)도 운영 부담이다.

## 결정

1. **1단계는 pgvector를 도입하지 않는다.** 후보 검색은 PostgreSQL 전문 검색(`tsvector` 생성 컬럼 + GIN)으로 한다.
   원문(`simple` 구성)과 학생 언어 번역을 함께 색인하고, 분류(`category`)가 질문에서 추정되면 가중치를 준다. 상위 K(기본 8)를 후보로 쓴다.
2. 후보는 반드시 `Notice.isGroundingEligible(today, lang)`를 통과한 것만이다(APPROVED, 유효기간 안, 번역 stale 아님). 이 필터는
   SQL이 아니라 **도메인 메서드**가 최종 판정한다. SQL은 1차 걸러내기만 한다.
3. LLM에는 후보 본문을 ID와 함께 넣고, "후보에 있는 내용만, 문장마다 `[ID]` 인용, 답할 수 없으면 정확히 `NO_GROUNDS`"를 지시한다.
4. **후처리 검증**이 최종 게이트다: 인용 ID 집합이 후보 집합의 부분집합이 아니거나 인용이 0개면 `NO_GROUNDS`로 강등하고 경고 로그를 남긴다.
   답변에 URL이 있으면 후보 Notice의 `sourceUrl`만 허용한다. 검증 실패를 "답변 없음"이 아니라 **강등 + 기록**으로 다루는 이유는
   LLM이 지시를 어긴 빈도를 봐야 프롬프트를 고칠 수 있기 때문이다.
5. 모든 Inquiry에 후보 ID·인용 ID·지연·모델 ID를 저장한다. 이것이 FTS의 재현율이 부족한지(후보에 정답 공지가 없어서 NO_GROUNDS가
   난 비율) 판단할 근거다.
6. **벡터 검색으로 바꾸는 조건**: Office 수가 늘어 자료가 수천 건이 되거나, NO_GROUNDS 중 "정답 공지가 있었는데 후보에 못 들어간" 비율이
   담당자 표본 검토에서 20%를 넘으면 pgvector(또는 외부 벡터 저장소)를 `NoticeSearchPort` 구현 교체로 도입한다. 포트는 처음부터 분리한다.

## 결과

- 장점: 운영 DB 변경이 Flyway 테이블·인덱스뿐이다. 자료 수정이 즉시 반영된다(재임베딩 없음). 비용은 LLM 호출뿐이다.
- 단점: 동의어·다른 표현의 질문은 FTS가 놓칠 수 있다. 특히 한국어 원문과 외국어 질문 사이는 번역 색인에 의존한다.
  이를 보완하려고 질문을 한국어로 한 번 번역해 원문 색인도 함께 검색하는 2단계 검색을 S3에서 실험한다(LLM 호출 1회 추가).
- S3 구현에서 정한 것(2026-10-31):
  - 질의는 AND 가 아니라 **OR**(`to_tsquery('simple', 'a | b | c')`)이다. 'simple' 구성은 불용어를 빼지 않아 "when does the …" 같은
    질문이 AND 로는 아무 문서도 못 찾는다. 짧은 기능어 몇 개만 제외하고, 매칭 여부는 `@@` 로 강제한 뒤 `ts_rank` 합으로 정렬한다
    (`ts_rank` 만으로는 매칭되지 않은 문서도 0 보다 큰 점수를 받는다).
  - 한국어·일본어·중국어 질문은 띄어쓰기 단위 FTS 가 약하다(조사가 붙은 "신청은"은 "신청"과 다른 토큰). 그래서 PG 어댑터가
    글자 2개 묶음(bigram) 점수(`KeywordNoticeSearchAdapter`)로 후보를 보강한다. 이 bigram 방식이 기본 구현이기도 하다
    (`ovlo.search.provider=keyword`, 로컬·테스트).
  - 두 구현은 `NoticeSearchPort` 뒤에 있고, 최종 근거 자격은 언제나 `Notice.isGroundingEligible` 이 판정한다.
- 테스트: FTS 어댑터는 Testcontainers PostgreSQL로 "만료 공지 제외", "다른 Office 공지 제외", "번역 stale 제외"를 고정한다.
  후처리 검증은 순수 단위 테스트(후보 밖 인용 → 강등, 인용 0 → NO_GROUNDS, 외부 URL 제거).
