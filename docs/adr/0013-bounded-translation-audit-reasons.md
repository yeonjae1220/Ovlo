# ADR-0013: 번역 의미 감사 사유의 제한된 기록

2026-11-17 · Accepted

운영 검증 공지 26의 중국어 번역은 구조 검사를 통과하고 의미 감사에서 거절됐다. 당시 구현은 `ALLOW/DENY`만 반환하고 거절된 번역문을 보관하지 않았다. 따라서 해당 요청의 정확한 표현이나 거절 사유를 사후 확정할 수 없다. 같은 원문을 다시 생성한 표본은 모두 통과했으므로 이를 원래 요청의 오탐이나 특정 어휘 문제로 단정하지 않는다.

비교 검증에서는 일반적인 `학교`를 `大学`로 좁히거나 원문에 없는 신입생 전용 조건을 추가한 중국어 문장을 거절했다. 번역 지시에는 중국어의 기관 범위와 참석 조건을 추정하지 않는 예시를 추가한다. 감사 지시에서는 `仅供…`, `仅用于…`, `…专用`처럼 동일한 용도 제한을 전달하는 표현을 표면 형태만으로 거절하지 않도록 명확히 한다. 의미 변경·누락·추가·미번역·조건 변경·불확실성은 계속 거절한다. 특정 공지나 중국어 전체에 대한 예외는 없다.

의미 감사의 단일 유료 호출에서 `decision`과 제한된 `reason` 코드를 함께 받는다. `NONE`은 `ALLOW`에만, `FACT_CHANGED / OMISSION / ADDITION / UNTRANSLATED / INSTRUCTION / UNCERTAIN`은 `DENY`에만 허용한다. 누락·알 수 없는 값·모순·추가 필드·중복 키·뒤따르는 JSON·중단된 출력은 모두 실패로 처리한다. 기존 질문 분류·답변 감사의 응답 계약은 바꾸지 않는다.

로그에는 목표 언어·판정·서버에서 검증한 코드만 남긴다. 자유형 설명, 원문, 번역문, 개인정보는 기록하지 않는다. 이 코드는 LLM이 보고한 분류이며 독립적으로 입증된 원인이라는 뜻은 아니다. 같은 스레드의 기존 공지 ID·언어별 거절 로그와 함께 조사한다. 파싱 실패는 고정된 `INVALID_RESPONSE`로 기록한다.

번역 Opus·감사 Sonnet, 입력·출력 상한, fallback 금지, 호출 수, 재시도 예산과 거절 작업의 수동 검토 경계는 유지한다. 프롬프트와 코드 출력에 필요한 토큰은 소폭 늘지만 감사 호출을 추가하지 않는다. 허용될 때까지 반복하거나 다수결로 거절을 덮어쓰지 않는다. 운영의 기존 거절 작업도 자동 초기화하지 않는다.

회귀 테스트는 응답 계약·모순 차단·본문 비로그를 고정한다. 유료 opt-in 검증은 합성 중국어 공지의 독립 생성 5회와 각 2회 감사, 동등한 용도 표지, 기관·대상·단위·금액·환불·지시문 변조 및 기존 6개 언어 검증을 포함한다. 모든 감사 결과를 저장하며 한 번의 실패도 성공 표본으로 덮지 않는다.

## 2026-11-17 후속: 공급자 거절 상세 비로그

공통 LLM 호출의 `stop_reason=refusal`에서도 자유형 `stop_details`를 기록하지 않는다. 공급자가 입력을 되풀이할 수 있으므로 기존 모델·고정 중단 상태·토큰·지연 지표만 유지한다. 답변·분류·답변 감사·번역·번역 감사 다섯 경로에서 실제 SDK와 로컬 HTTP 응답으로 합성 개인정보의 로그·반환값 비노출을 회귀 검사한다. 실제 공급자가 개인정보를 반환했거나 운영에서 유출됐다는 주장은 하지 않는다.
